# Deployment – Fix for `_next/static/chunks/*` 404

## Why you see 404 for JS/CSS chunks

The browser loads the HTML from `https://justbuytravel.com/`, but the `<script>` and `<link>` tags point to URLs like:

- `/_next/static/chunks/36d10c0834bed00a.js`
- `/_next/static/chunks/9fe6f7898f175d5e.css`

Those files are generated by `next build` and live under `.next/static/`. If the server does not serve the contents of `.next/static/` at the path `/_next/static/`, the browser gets **404** for those URLs and the app breaks.

Common causes:

1. **Only HTML was deployed** – The full build output (`.next/` and especially `.next/static/`) was not uploaded or is not on the same server/path.
2. **Wrong process running** – Something other than the Next.js server (e.g. static file server or wrong app) is serving the domain, so `/_next/static/*` is not handled.
3. **Reverse proxy** – Nginx/Apache is not forwarding `/_next/*` to the Next.js app (or not serving `.next/static`).
4. **Stale/cached HTML** – An old HTML page is cached and still references old chunk filenames that no longer exist after a new deploy.

## What was changed in this project

1. **`next.config.mjs`**  
   - `output: "standalone"` was added so the build produces a self-contained app under `.next/standalone/`.

2. **`scripts/copy-standalone-static.js`**  
   - After `next build`, this script copies:
     - `.next/static` → `.next/standalone/.next/static`
     - `public` → `.next/standalone/public`  
   So when you run the app from the standalone folder, `/_next/static/*` and `/public/*` are available.

3. **`package.json` build script**  
   - The build now runs this copy script after `next build`.

## How to deploy so chunks are not 404

### Option A: Run Next.js on the server (recommended)

1. On the server, run a **fresh** build:
   ```bash
   npm run build
   ```
2. Start the app:
   ```bash
   npm start
   ```
   Or, if you deploy only the standalone output:
   ```bash
   cd .next/standalone
   node server.js
   ```
   (Ensure `.next/standalone` contains `.next/static` and `public` as above.)

3. Point the domain to this Node process (e.g. with a process manager like PM2 and Nginx/Apache in front).  
4. In Nginx (or similar), **proxy** the whole site (including `/_next/*`) to the Next.js app:
   ```nginx
   location / {
       proxy_pass http://localhost:3000;
       proxy_http_version 1.1;
       proxy_set_header Upgrade $http_upgrade;
       proxy_set_header Connection 'upgrade';
       proxy_set_header Host $host;
       proxy_cache_bypass $http_upgrade;
   }
   ```
   Do **not** serve only the root URL and leave `/_next/*` to a different (or no) handler.

### Option B: Same server, correct static serving

If you serve the app without the Node server (e.g. static/cPanel setup):

1. After `npm run build`, upload **both**:
   - The built app (e.g. `.next/standalone` or whatever your host expects).
   - The contents of **`.next/static`** so they are available at **`/_next/static/`** on the same domain (e.g. `https://justbuytravel.com/_next/static/...`).

2. Ensure the server (or CDN) is configured to serve `/_next/static/*` from that directory. Chunk filenames change every build, so **do not** cache HTML aggressively without invalidating it on deploy, or you’ll get 404 for old chunk names.

### Checklist

- [ ] `npm run build` completes and `.next/static/` (and `.next/standalone/` if used) exists.
- [ ] The process that serves `https://justbuytravel.com/` is the Next.js app (e.g. `next start` or `node .next/standalone/server.js`), **or** the same server serves `/_next/static/` from the **current** build’s `.next/static/`.
- [ ] Reverse proxy (if any) forwards `/_next/*` to the Next.js app (or to the place where `.next/static` is served).
- [ ] No old cached HTML that references previous chunk hashes; clear CDN/browser cache after deploy if needed.
- [ ] If you use `NEXT_PUBLIC_BASE_PATH`, the site is opened with that path (e.g. `https://justbuytravel.com/your-base-path/`), otherwise asset paths may point to the wrong place.

After fixing deployment so `/_next/static/chunks/*` are served from the current build, the 404 errors for those URLs will stop.
